# 无线连接（无线调试）设计方案

> 状态：基础版已实现（2026-11-12，对应 CHANGELOG 1.1.0；待真机实测）
> 目标：让 AndroidReLive 在「插 USB」之外，支持通过**无线调试**连接设备，
> 做到「同 Wi-Fi + 一次性配对」后免数据线管理（镜像 / 文件 / 终端 / 应用全功能）。

---

## 1. 背景与用户诉求

当前连接只有 WebUSB 一条路，必须插线。开发者选项里的「无线调试」（Android 11+）
能在不插 USB 的情况下开启 ADB over Wi-Fi，但需要**同 Wi-Fi + 首次配对**。

用户的两点期望（2026-11-12 沟通确认）：
1. **手动指定 IP:端口连接**（最朴素的形态）；
2. **更好**：自动识别内网中已开启无线调试的设备，点一下就连。

结论：两条都要，且「自动识别」正好对应 Android 无线调试的 mDNS 广播机制，
技术上顺理成章。

---

## 2. 现状盘点（已具备 / 缺失）

### 2.1 客户端已具备（在 `js/core/transport.js`）
| 函数 | 作用 | 说明 |
|---|---|---|
| `connectServer({bridge, target})` | 经桥接走「ADB 服务端」模式 | 内部已调用 `client.wireless.connect(target)` 与 `getDevices()` |
| `connectTcp({bridge, target})` | 经桥接直连 `host:port` | 对应「手动填 IP」场景 |
| `bridgeRequest(base, path, data)` | 向桥发 POST JSON | 用于 `/start-server`、发现等控制指令 |
| `byteChannel(base, route, {signal})` | 与桥建立 WebSocket 字节流 | 承载 ADB 协议字节 |

> 也就是说，**前端到桥的传输通道、到 ADB 的认证/驱动（`Driver`）全部复用**，
> 无线只是把 `transport` 层的连接器从「WebUSB」换成「WebSocket→桥」。

### 2.2 依赖库已具备（在 `node_modules/@yume-chan/adb`）
- `server/commands/wireless.ts` → `WirelessCommands`：`pair(address, password)` / `connect(address)` / `disconnect(address)`（含 TLS 握手）
- `server/commands/m-dns.ts` → `MDnsCommands`：`check()` / `getServices()`（返回 `{name, service, address}[]`）
- `server/client.ts` → `AdbServerClient`：服务端协议客户端原语（`createAdb`、`getDevices` 等）

### 2.3 缺失（本次要补的）
1. **桥接服务端程序**：一个本地 Node 程序，把上面的 `wireless` / `mDns` 能力用
   WebSocket + HTTP 包出去。原 ya-webadb 的 bridge 在精简时被删了，需重建（可移植其实现，同为 GPL-3.0）。
2. **UI 无线面板**：连接方式切换、设备发现列表、手动 IP、配对码输入。
3. **配对流程**：现有 `connectServer` 只做 `connect`，未做首次 `pair`；新设备需先 `pair(配对地址, 配对码)` 再 `connect(连接地址)`。

## 3. 架构

```
┌─────────────────────────────────────────────────────────────┐
│ 浏览器（Chrome/Edge，http://127.0.0.1:8125）                 │
│  index.html + js/relive-page.js（UI）                         │
│  js/core/transport.js → connectServer / connectTcp            │
│         │  WebSocket（localhost，电脑内部）                   │
│         ▼                                                    │
│  桥接程序 bridge.cjs（本地，:8126，仅绑 127.0.0.1）          │
│   路由：/start-server  /server(WS)  /adb(WS)  /mdns          │
│   内部复用 @yume-chan/adb 的 wireless.* / mDns.*             │
│         │  Wi-Fi / TCP(+TLS)                                 │
│         ▼                                                    │
│  手机：开发者选项 → 无线调试（mDNS 广播 + TLS 配对端口）      │
└─────────────────────────────────────────────────────────────┘
```

- **USB 模式**（现有）：浏览器 → WebUSB → 手机。零额外软件。
- **无线模式**（新增）：浏览器 → localhost WS → 桥 → Wi-Fi → 手机。
  多一个本地桥进程，但页面交互一致。

## 4. 交互流程

### 4.1 自动发现（用户最想要）
1. 手机开启「无线调试」。
2. 页面「无线」面板点「扫描设备」→ 调用桥 `GET /mdns` → `mDns.getServices()`
   → 返回内网已可连接的设备列表（地址形如 `192.168.x.x:xxxx`）。
3. 用户点某设备 → `connectServer({bridge, target})` → 内部 `wireless.connect` → 进主界面。
   （这些是已经配对过 / 用传统 tcpip 开的设备，可直接连。）

### 4.2 手动指定 IP（朴素形态）
面板填 `IP:端口` → `connectTcp({bridge, target})` 直连。
适合已知道地址、或自动发现失灵时兜底。

### 4.3 新设备首次配对（一次性）
手机的「无线调试」界面会给一个**配对地址**（如 `192.168.1.50:37000`）和 **6 位配对码**。
1. 面板「添加新设备」填配对地址 + 配对码 → 桥调用 `wireless.pair(配对地址, 码)`。
2. 配对成功后，设备出现在 4.1 的发现列表（或自动尝试 `connect` 连接地址）。
3. 之后同 Wi-Fi 下免重复配对。

> 设计重点：`pair` 与 `connect` 是两个不同地址/动作，UI 要明确区分「配对」与「连接」，
> 不能只给一个 IP 框。

## 5. 桥接服务端设计（bridge.cjs）

职责：
- 启动一个 HTTP + WebSocket 服务，**仅绑定 `127.0.0.1`**（不暴露到局域网）。
- 实现 `AdbServerClient.ServerConnector` 契约：
  - `connect()`：开一个 `/server` WebSocket，把字节流对接到内部 ADB 服务端协议。
  - `addReverseTunnel` / `removeReverseTunnel`：按需实现（无线模式可不提供，报错提示即可）。
- 提供控制路由：
  - `POST /start-server`：唤醒/确认服务端（对应 `bridgeRequest` 调用）。
  - `WS /server`：承载 ADB 服务端协议（设备列表、connect、createAdb…）。
  - `WS /adb?host=&port=`：直连某个 TCP ADB（对应 `connectTcp`）。
  - `GET /mdns`：返回 `mDns.getServices()` 结果（供发现列表）。
- 内部用 `@yume-chan/adb` 的 `WirelessCommands` / `MDnsCommands` 真正干活。
- 可选：启动 token，防止本机其他网页乱连（先不做，留接口）。

实现来源：优先**移植 ya-webadb 原 bridge**（同 GPL-3.0，合规），
把精简时删掉的服务端逻辑恢复并裁剪到只保留无线/网络所需，避免从零写 ADB 服务端协议。

依赖新增（按需）：
- mDNS 多播库（ya-webadb 用的那一个，如 `multicast-dns` 或 `@yume-chan` 自带），用于 `getServices`。
- 其余 ADB/TLS 能力库已具备。

## 6. 前端改动（js/relive-page.js + index.html + css）

- 顶部/侧边增加「连接方式」切换：**USB ｜ 无线**。
- 「无线」面板包含：
  - 「扫描设备」按钮 + 设备列表（来自 `/mdns`）；
  - 手动 `IP:端口` 输入框 + 「连接」；
  - 「添加新设备（配对）」：配对地址 + 配对码 + 「配对」；
  - 桥地址设置（默认 `ws://127.0.0.1:8126`，可改；连不上时提示「请先启动桥接程序」）。
- 连接成功后，后续镜像/文件/终端/应用**完全复用现有 `Driver`**，不改动。
- `transport.js` 微调：在 `connectServer` 流程里补一个可选的「先 pair 再 connect」入口
  （新增 `pairThenConnect({bridge, pairAddress, code, connectAddress})`），其余不动。

## 7. 安全

- 桥仅绑 `127.0.0.1`，外部无法直连；ADB 端口不暴露在局域网。
- 无线调试本身等同「同 Wi-Fi 可读写手机」，公共 Wi-Fi 有风险——文档里明确提示
  「仅在可信 Wi-Fi 使用，用完可在手机端关闭无线调试」。
- 后续可加启动 token（接口已留）。

## 8. 里程碑（建议顺序）

1. **M1 桥接骨架**：`bridge.cjs` 起服务 + `/start-server` + `/server` WS，能跑通 `connectServer`
   连一个已配对设备（手动给地址）。验证传输链路。
2. **M2 手动 IP 直连**：`connectTcp` + UI 手动框，覆盖「填 IP 就连」。
3. **M3 自动发现**：桥 `/mdns` + UI 扫描列表，覆盖「自动识别设备」。
4. **M4 新设备配对**：`wireless.pair` 流程 + UI「添加新设备」，覆盖首次配对。
5. **M5 打磨**：错误提示（桥未启动、配对码错、设备离线）、README/帮助文档、自检脚本纳入 `npm run check`。

---

## 9. 风险与待确认

- **桥的 ADB 服务端协议实现**是唯一非平凡块。对策：移植 ya-webadb bridge，不自己造。
- mDNS 在部分路由器/网络下不广播（隔离 AP），届时退回「手动 IP」。
- 无线调试端口每次开启可能变化（部分机型随机），所以「自动发现」比「记死 IP」更稳。
- 页面需安全上下文：当前 `http://127.0.0.1` 满足；若以后上公网域名需 HTTPS。

## 11. 修订：全设备覆盖（v1.2.0 实现）

### 11.1 为什么原方案不够

原设计只覆盖 Android 11+ 的「无线调试配对」。实际使用中它有两个硬伤：

1. **信任是按电脑公钥记的**。换一台电脑（哪怕同一部手机）就等于换了一把钥匙，
   而很多用户并不知道「那台电脑以前插线授权过」，于是表现为「怎么配都配不上」。
2. **Android 10 及更早、智能电视、机顶盒根本没有这个配对界面**。它们只有 `adbd` 监听 TCP 端口
   这一条路，原方案对这类设备完全无能为力。

### 11.2 三条通道（按设备自动对号入座）

| 通道 | 适用 | 桥接动作 | 前置条件 | 之后 |
|---|---|---|---|---|
| ① USB 引导 `tcpip` | **所有** Android 版本，含无配对界面的老设备 | `adb tcpip <port>` → 从设备 `ip addr` 读局域网 IP → `adb connect ip:port` | 一次 USB 连接 + USB 调试授权 | 固定端口，重启设备后需重来一次 |
| ② 局域网端口扫描 | 老手机、智能电视、盒子 | 并发 TCP 探测本网段 5555（254 台约 1 秒），命中即 `adb connect` | 设备已开「网络调试 / ADB 调试」 | 固定 5555，重启后点「重连」 |
| ③ mDNS + 配对码 | Android 11+ | 轮询 `_adb-tls-pairing` 拿地址 → `adb pair` → 等 `_adb-tls-connect` 新端口 → `adb connect` | 手机开「无线调试」 | 钥匙写入设备信任列表，永久有效 |

三条通道最终都落到 `adb connect`，因此**不绕过 ADB 授权模型**，也不引入任何 root / 漏洞利用。

### 11.3 关键实现决策

- **只给 IP 也能连**（`/link/connect`）：先问 mDNS 当前 TLS 端口，再退 5555/5556，解决端口漂移。
- **区分「未配对」和「网络不通」**：若端口来自 mDNS 广播、TCP 探测可达，但 `adb connect` 失败，
  判定为本电脑未被信任（`needPair`），直接引导去配对，而不是甩一句 `failed to connect`。
- **配对码自动抓取**：前端每 1.5s 轮询 `/link/probe`，配对弹窗一开就自动填地址，用户只需输 6 位数字。
- **设备档案**（`.tmp/known-devices.json`，已在 `.gitignore`）：记住连过的地址与型号，支持一键重连；
  端口变化由 mDNS 自愈。档案只存本机，不随项目分发。
- **扫描性能**：128 并发、400ms 超时，/24 网段约 1 秒；默认只扫 5555，避免误报其他服务。

### 11.4 仍然存在的边界（不夸大）

- 设备若关闭了「USB 调试 / 网络调试」，任何工具都无法连接——这是设备侧开关，不是软件能绕过的。
- 路由器开启 AP 隔离 / 客户端隔离时，设备之间互相不可达；此时代码无法修复，只能换网络或用 USB。
- USB 引导的 `tcpip` 模式**不加密**（明文 TCP），仅建议在可信局域网使用；Android 11+ 优先走通道 ③（TLS）。
