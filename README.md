# 安卓重生 AndroidReLive_ZPH

> 在浏览器里直接投屏、操作、传文件、装应用、开终端 —— 把碎屏机、闲置平板、抽屉里的旧手机，
> 重新变成一块**能用的屏幕**。

纯前端，不用装客户端、不用后端服务器、不用 root。设备数据只在你自己的 USB 线里走。

- **免安装**：浏览器打开就能用，什么都不用装到手机上
- **免后端**：全部在你本机浏览器里跑，没有云端中转
- **数据不过网**：WebUSB 直连设备，画面和文件都不出电脑
- **开源**：GPL-3.0，欢迎继续改

## 怎么跑起来

前提：电脑装了 [Node.js](https://nodejs.org/)（14 以上即可），浏览器用 **Chrome / Edge 等 Chromium 内核**。

### 方式一：一键启动（推荐，日常用）

项目根目录有两个启动文件，**双击即可**，不用开黑框、不用手敲命令：

| 文件 | 作用 |
|------|------|
| **`start.vbs`** | 后台静默启动（网页服务 + 无线桥一起拉起），自动弹浏览器，**没有黑框**。日常用这个。 |
| `start.bat` | 同样一键启动，但会保留一个黑色命令行窗口方便看实时日志。调试时用这个。 |

> 想关掉：双击 `stop.vbs` 即可干净退出；用 `start.bat` 的话在黑框里按 `Ctrl+C`。
> 一键启动会把运行日志写到根目录 `launcher.log`，排查问题时可以翻。

### 方式二：手动启动（开发 / 排查用）

```bash
# 1. 进目录
cd AndroidReLive_ZPH

# 2. 起本地服务（不需要 npm install，构建产物已随仓库提供）
npm start

# 3. 浏览器打开
#    http://127.0.0.1:8125
```

打开就是控制台 → 点「连接设备」→ 在弹出的列表里选中你的手机/平板。

**必须走 `http://127.0.0.1:8125`，不能直接双击 HTML 文件打开。**
`file://` 协议下浏览器的 ES 模块和 WebUSB 会被安全策略拦住，表现就是白屏或按钮点不动 —— 这是最容易卡住的一步。

端口被占了就换一个：`PORT=8200 npm start`（Windows cmd 用 `set PORT=8200 && npm start`）。

## 无线连接（无线调试）

无线连接最大的坑不是网络，而是「信任」：ADB 只认**电脑的密钥**，不是认人。所以换一台电脑、换一个设备，
都要重新建立一次信任。本项目把这件事拆成**三条通道**，按设备年代自动对号入座，不用记命令、不用手抄端口：

| 设备 | 点哪个按钮 | 会发生什么 | 之后 |
|---|---|---|---|
| **Android 11+ 手机/平板** | 一键发现设备 | mDNS 自动找到调试端口，列表出现「需配对码」；点「等待配对码」会自动抓地址，输 6 位数字即配对+连接 | 配对只需一次，永久有效；端口每次变都能自动找回 |
| **Android 10 及更老、智能电视、盒子** | 扫局域网（电视/老设备） | 扫描本网段的 5555 端口（老设备没有配对机制，adbd 就监听在这里），设备屏幕上点一次「允许」 | 走固定 5555，重启设备后点「重连」即可 |
| **任何安卓设备（最稳的兜底）** | USB 一键开启无线 | 插线 → `adb tcpip 5555` → 自动读取设备 IP → 连接 → 记住设备 | 拔线即无线；重启设备后重复一次（约 10 秒） |

> **为什么办公室那台电脑一连就上，新电脑怎么都不行？**
> 因为那台电脑的 `adbkey.pub` 早就被写进了设备的信任列表（以前插线授权过，或配对过）。信任是记在
> 「电脑」身上的，换电脑就等于换了一把钥匙，设备自然不认。这也是三条通道存在的意义：把「重新建立信任」
> 变成一次点击，而不是一堆命令。

> 注意：这套能力本质是「电脑经局域网读写设备」，只建议在**自己家的可信网络**下使用；用完在设备上关掉调试开关即可。

### 准备
1. `adb` 已随项目内置在 `bin/` 目录（Windows 为 `adb.exe` + 两个 DLL），**clone 下来即可直接用，无需另装**。
   - 桥接程序会优先使用项目自带的 `bin/adb.exe`，找不到时才依次尝试常见位置（Android SDK 的 `platform-tools/adb.exe`、PATH 中的 `adb`）。
   - 想用自己的 adb：设置环境变量 `ADB_BIN` 指向它即可（优先级最高）。
   - 内置 adb 来自 Android 官方 platform-tools（Apache-2.0，许可证见 `bin/NOTICE.txt`）。
2. 设备侧开关：
   - 手机/平板：设置 → 开发者选项 → **无线调试**（Android 11+）或 **USB 调试**（老系统，配合 USB 通道）。
   - 智能电视/盒子：设置 → 关于 → 连点「版本号 / Android TV OS 构建版本」7 次 → 开发者选项 → 打开 **USB 调试 / ADB 调试 / 网络调试**。
3. 电脑与设备在**同一局域网**（同一 Wi-Fi，或电视插网线、电脑同一路由器）。路由器若开了「AP 隔离 / 客户端隔离」，
   设备之间互相不通，任何工具都连不上。

### 启动桥接
- **一键启动用户不用管**：`start.vbs` / `start.bat` 已经自动把「无线桥」和「网页服务」一起拉起来了，直接连就行。
- **手动启动用户**：如果没用一键启动，需要自己先把桥开起来：
```bash
npm run bridge        # 启动无线桥接程序，默认 127.0.0.1:8126
```
保持它运行（无线模式下浏览器要借它把数据转给设备），再开 `npm start` 的网页。

### 在网页里连接
1. 顶栏把连接方式从 **USB** 切到 **无线**。
2. 点「桥接地址」右边的「测试」，确认显示「桥已连」。
3. 按上表选一个按钮。列表会按来源分组打标签：
   - **USB**：插着的设备，点「开启无线」一次性把无线开起来；
   - **需配对码**：点「去配对」或用「等待配对码」自动抓地址，输满 6 位自动配对并连接；
   - **可直连**：直接点「连接」；
   - **常用**：连过的设备，点「重连」自动找回当前端口（端口变了也不用管）。
4. 「手动 IP:端口」是最后兜底：实在自动发现不了时，填设备屏幕上显示的地址（手机填无线调试里的**连接地址**，
   电视/老设备一般填 `IP:5555`）。
5. 连接成功后，镜像 / 文件 / 应用 / 终端**和 USB 模式完全一致**。

> 连不上时先看右侧日志：现在会明确区分「未配对」「未授权」「网络不通」三种情况并给出下一步，
> 不再只甩一句 `failed to connect`。

端口：`BRIDGE_PORT=8201 npm run bridge` 可换桥接端口（Windows cmd 用 `set BRIDGE_PORT=8201 && npm run bridge`）。

## 它能干什么

| 能力 | 说明 |
|---|---|
| **实时镜像** | 设备画面实时投到浏览器，鼠标点击拖动、滚轮、键盘输入都能落到设备上 |
| **熄屏唤醒** | 设备黑屏时先自动点亮再启动；顶栏「唤醒」可随时再叫一次 |
| **桌面式窗口** | 镜像铺底当桌面，文件/应用/终端/状态/截图都是可拖动、可最小化的窗口，位置自动记住 |
| **文件管理** | 浏览设备目录、上传下载、图片视频在线预览（可全屏） |
| **应用管理** | 启用 / 禁用 / 卸载 / 恢复系统应用，安装 APK、提取安装包、导出应用清单 |
| **ADB 终端** | 在设备上直接敲 shell 命令，带历史记录和 xterm 渲染 |
| **设备状态** | 电池、屏幕、编码器、CPU 等信息一屏看全 |
| **截图** | 一键截取设备画面并保存到本机 |
| **声音同步** | 手机播放的声音实时同步到电脑（需 Android 12+ 且 Chrome/Edge） |
| **音量浮层** | 点右下角 🔊 弹出（仿 Windows）：第一行直接调**平板媒体音量**，展开可调通话/铃声/通知/闹钟四路，第二行是电脑端播放音量 |

界面按 Windows 的习惯分三层，顶栏只留高频操作：

- **顶栏**：连接 / 断开、主屏镜像、返回桌面任务导航、松手、唤醒、详细日志、专注模式；
- **左下角「开始」菜单**：文件管理、应用管理、ADB 终端、设备状态、截图（都是可拖动窗口，最小化收进任务栏）；
- **右下角状态栏**：设备名、电量、🔊 音量浮层、时钟。

## 使用前必读

1. 设备进「开发者选项」，打开 **USB 调试**。
   - 小米 / 红米 / POCO 还要额外打开 **「USB 调试（安全设置）」**，然后**重启设备**。
     不开这一项，画面能看但**鼠标键盘点了没反应**（系统拒绝模拟点击）。
2. 用**能传数据的线**连电脑（很多充电线只有电源针脚）。
3. 设备弹出「允许 USB 调试吗」时，勾「一律允许」再确定。
4. 同一个 USB 接口同时只能被一个程序占用。若提示被占，先关掉电脑上的 adb.exe 或其他 WebADB 页面。

```
├── js/
│   ├── relive-page.js         控制台页面逻辑：按钮、日志、界面切换（不用构建）
│   ├── core/                  核心命令层（原生 ES 模块，改完直接刷新，不用构建）

├── scripts/

└── licenses/                            第三方许可原文
```

**两层源码的分工，是理解这个项目的关键：**

- `src/` 是**要构建**的（`npm run build` → `js/vendor/relive.bundle.js`），投屏会话、窗口、面板这些复杂逻辑都在这。
- `js/core/` 是**原生 ES 模块，浏览器直接加载**，改完刷新页面就生效，不用构建。
- `js/vendor/` 里的东西**一律不要手改**：要么是第三方库，要么是构建产物（改了会被下次构建覆盖）。

## 开发

```bash
npm install          # 只有要改 src/ 并重新构建时才需要
npm run build        # 构建 src/ → js/vendor/relive.bundle.js
npm run watch        # 改 src/ 时自动重建
npm run check        # 自检：产物符号齐全 + 页面引用都能打开（改目录后必跑）
npm start            # 起服务（127.0.0.1:8125）
```

改了 `src/` 里的代码，**必须 `npm run build` 再刷新页面**，否则跑的仍是旧产物 —— 这是第二大坑。
只改 `js/core/`、`css/`、`*.html` 的话，直接刷新即可。

架构分层、各模块职责、以及开发中踩过的 6 个深坑（含"关掉镜像再打开必崩"的完整根因），
见 [docs/开发指南.md](./docs/开发指南.md)。

## 常见问题

**白屏 / 按钮全灰 / 控制台报模块加载失败**
多半是直接双击 HTML 打开的。必须 `npm start` 后访问 `http://127.0.0.1:8125`。

**端口被占用**
`PORT=8200 npm start` 换一个端口（Windows cmd 用 `set PORT=8200 && npm start`）。一键启动时改端口见 `launcher.mjs` 顶部的 `ports` 配置。

**浏览器里选不到设备**
① 线是不是数据线；② USB 调试开了没；③ 有没有别的程序（adb.exe、其他 WebADB 页面）占着这个接口；④ 换根线或换个 USB 口。

**画面能动，但鼠标点了没反应**
小米系设备要开「USB 调试（安全设置）」并重启。控制台顶栏会显示黄色提示条，里面有对应机型的操作路径。

**设备有声音，但电脑听不到**
① 镜像起来后一般直接就有声；没声就点一下右下角 🔊（那次点击会唤醒浏览器音频，标签页才会出现小喇叭），顺手也能看到/调整平板媒体音量；
② 需 Android 12+（scrcpy 音频要求）且用 Chrome / Edge（要 WebCodecs 音频解码），老设备无声音属正常；
③ 仍没声：**先硬刷新页面（Ctrl+Shift+R）再连一次**，把右侧运行日志里带 **`[音频]`** 的行整段贴出来。
   重点看三行：`音频收到配置包`（长度是否 >0）、`音频解码器配置完成`（codec/声道/采样率）、`音频上下文状态`。
   - 若日志出现「`未收到标准 OpusHead，已合成默认头`」属正常兜底，不影响出声；
   - 若日志出现「`音频解码器异常，正在自动重建`」→ 解码器某帧失败后已自动重建，多数能恢复；
   - 若出现「`音频解码器重建后仍不可用，已停止音频`」说明该浏览器/设备组合解码失败，把日志贴出排查（投屏画面不受影响）；
   - 新增「`音频解码能力探测`」一行：连接时先问浏览器认不认 opus，显示"不支持"即该浏览器解不了设备的声音（换 Chrome/Edge 最新版试试）。
   老版本会疯狂刷「`音频解码抛异常：Failed to execute 'decode'`」属已知 bug，已修复：现在解码失败只打一条**完整诊断**（错误名 / 帧长 / 帧头十六进制），连续失败 3 次自动安静停止，不再刷屏。若仍无声，把那一条诊断整行贴出来即可精确定位。

**"关闭镜像再打开"卡住**
已修（v1.0.0）。根因是设备端的投屏程序文件被系统清掉，重启时加载不到类。现在每次启动前会核对文件大小、按需重推。
如果还遇到，把控制台右侧日志里带 `[清理]`、`scrcpy-server` 的行贴出来。

## 兼容性

| 情况 | 说明 |
|---|---|
| 浏览器 | 只支持 Chromium 内核（Chrome、Edge、QQ/360 极速模式等）。Firefox、Safari 不支持 WebUSB。 |
| Android 版本 | 一般 Android 7 以上都行；实测 Android 13 平板正常。 |
| 部分展锐 / 联发科平台 | 只有一个硬件 H.264 编码器，主屏投屏占用后无法再开虚拟第二块屏。所以本项目只做**单路主屏镜像**。 |
| USB 接口独占 | 浏览器、adb.exe、别的 WebADB 页面，同一时刻只能有一个占用接口。 |
| 无线调试 | 需 Android 11+ 且开启「无线调试」；电脑端要能找到 `adb`（无线模式会多起一个本地 `bridge.mjs`）。同一可信 Wi-Fi 下使用。 |
| 声音同步 | 需 Android 12+（scrcpy 音频要求）且用 Chrome / Edge（要 WebCodecs 音频解码）。Android 11 及以下设备无声音属正常。 |
| 平板音量 | 走设备端 `cmd media_session volume`；个别老机型只有 `media volume` 也能用。两条都不给用的机型，音量行会显示原文，投屏不受影响。 |
